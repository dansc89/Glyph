# Drawbridge 6.0 → Glyph: complete active-workflow parity and acceptance plan

## Decision and exact scope

**Success means complete active Drawbridge 6.0 workflow parity or better in native Omarchy Glyph. A text increment, passing suite, or completion of the 6.0 release delta alone is not success. Glyph does not currently meet that threshold.** This document replaces the target, not the historical v5.5 documents; those remain unchanged.

Read-only audit; no build, test execution, installation, GUI operation, source modification, commit, or release was performed by this audit. The sole owned deliverable is this document. Existing test results below are inspected evidence, not new audit executions. Drawbridge is macOS/PDFKit/CoreText/Vision code and cannot be executed comparably on this Linux host. Source review establishes behavior and wiring, not runtime or cross-platform performance equivalence.

### Status meanings (no parity score)

- **Implemented-and-tested (bounded)**: active implementation plus recorded passing tests for the explicitly stated supported behavior. Not shorthand for complete 6.0 parity, production Wayland acceptance, or fresh root acceptance.
- **Partial**: a real supported subset exists, but a concrete reference behavior is missing or constrained differently.
- **Missing**: no equivalent active Glyph workflow in the inspected UI/command/backend surface. Negative findings are scoped to that surface, not assertions about every future branch or external tool.
- **Unverified**: relevant code/evidence exists, but no sufficient test evidence establishes the requested outcome. A code path or test name alone is not a pass.
- **Inactive reference / not a parity requirement**: surviving legacy implementation is unreachable from the exact reference's active UI. This is an explicit inventory outcome, not a missing feature silently omitted.

## Safety and persistence gates applied to EACH active workflow

A workflow cannot be accepted by its row's happy path alone. Apply these to W01–W35, marking a genuinely non-mutating operation's write checks as **asserted read-only**, not silently omitting them.

- **S1 Identity/ownership:** document generation/path/page/object and draft/modal ownership validated at input, worker submission and publication. Stale results, wrong page/object, foreign links/widgets, and author spoofing must not mutate or disclose another document. Multi-tab state cannot cross-load.
- **S2 Cancellation and no-op:** Escape, focus loss (documented policy), picker Cancel, outside click, confirmation Cancel, invalid input, empty selection and identical update leave source bytes/dirty checkpoint/history unchanged as appropriate. Deferred saves cannot become ordinary Save when Save As was requested. Cancelled Save As may retain valid committed **unsaved** draft; never write original through intent confusion.
- **S3 Shared transactional history:** exactly one history entry per committed gesture/edit and one group per batch; empty Undo/Redo does no I/O. Draft-local text history cannot consume document history. Undo/Redo then Save/reopen each state; retain valid history after Save where reference promises it. New annotation kinds/page/outline/link/author metadata included in validation, not an overlay-only model.
- **S4 Preserve source and imports:** compare original decoded page streams, crop/media boxes, rotation/UserUnit, resource/XObject graphs, foreign annotations/AP/metadata, forms, labels, bookmarks and links. Only declared edit scope changes; appearance copy-on-write where resources are shared. Independent parser and rendering verification, including masks outside edited bounds.
- **S5 Security and conflicts:** encrypted/signed/signature-field/permission-protected documents refuse unsafe changes. Source replacements/in-place modifications, symlinks, destination collision and unwritable/full storage are explicit errors. No secure-redaction promise. Test exact source hash/identity checks before and after commit; report actual post-exchange state and permanent backup, not a fictional rollback guarantee.
- **S6 Durable publication/recovery:** staged output parses and expected changes verify before publish; no-clobber Save As, exact previous-byte backup for overwrite, appropriate sync/directory durability and failure reporting. Exercise failures at serialization, stage verification, rename/exchange and refresh; retain open edits and recovery context. Crash tests distinguish a verified saved file, backup of previous source and unsaved-session recovery.
- **S7 State/input accessibility:** keyboard/mouse/text editor/menu/modal each owns intended commands; same-frame typing/save or gesture/release/save commits correct latest input exactly once. Minimum supported window, fractional DPI, light/dark theme, offscreen controls and accessible labels; hidden/disabled actions cannot bypass guards. Native clipboard/portal/printer failures visible and recoverable.
- **S8 Scope/privacy:** generated fixtures first; authorized corpus only, private paths/content not published in screenshots/logs/reports. No tests on real source PDFs in place. External URLs/actions only on explicit user activation; no secret capture. OS picker/print dialog cancellation not approximated by backend tests in final native acceptance.

## Scope and confidence

Findings describe the source inspected during the audit, before any concurrent line/arrow implementation is verified. Inspected README, actual menu/toolbar wiring, Swift interaction/persistence code, and Rust UI/PDF implementations—not release notes alone. No build, tests, GUI, publishing, or private PDFs were used. **Implemented means source-wired, not newly runtime-verified.** Missing means absent from the inspected active UI and relevant source paths; dormant functions do not qualify as working UI features.

Citations below use `D/` = `/home/daniel/.cache/drawbridge-v5.5-reference/` and `G/` = `/home/daniel/.cache/glyph-v55-parity/`, followed by path and one-based line ranges. Status describes Glyph relative to the usable Drawbridge workflow. Priority: P0 protect foundations; P1 highest-value parity; P2 subsequent completeness.

## Critical reference trap

`D/Sources/Drawbridge/ToolMode.swift:23–36` disables the **legacy** authoring path. It does **not** mean 5.5 lacks markup: a separate `RectangleMarkupController` and `RectangleMarkupToolbar` actively expose pen, rectangle, ellipse, line, arrow, polygon, polyline, text, and properties. See `D/Sources/Drawbridge/RectangleMarkupToolbar.swift:23–49,86–129,171–210` and `D/Sources/Drawbridge/RectangleMarkup.swift:212,344–443,451–560`. Conversely, enum members and old command methods alone do not establish measurement, cloud, callout, image conversion, or batch combine availability.

## What should NOT be counted as 5.5 gaps

- Measurement/calibration/area takeoff and page-conversion tools: Drawbridge README explicitly says measurement and page-conversion are not available (`D/README.md:5`); legacy `ToolMode` paths are disabled (`D/Sources/Drawbridge/ToolMode.swift:23–36`).
- Batch combine, JPEG export/rebuild, mobile export and images-to-PDF have legacy command methods (`D/Sources/Drawbridge/MainViewController+Commands.swift:159–167,534`) but are not exposed in the exact active File menu (`D/Sources/Drawbridge/AppDelegate.swift:186–221`). Do not promote them to required user-facing 5.5 parity merely because code survives.
- Cloud/callout/note/highlighter legacy enum cases are not active new-toolbar tools. Arbitrary imported annotation editing is also not a required promise: Drawbridge says imported annotations remain visible/preserved (`D/README.md:42`).

## Recommendation: highest-value next increment

1. **Proceed with line/arrow**: conclusively missing and good bounded expansion of existing shape authoring. Match two-click start/end, preview, Escape cancel, same-page bounds, nonzero minimum length, owned-annotation selection/delete, shared undo/redo, Save and reopen. Use true PDF `/Line` endpoints and `/LE` arrow style plus an appearance stream; a viewer-only overlay is not delivery. Keep compact L/A icons and shortcuts, with focus/modal guards.
2. **Most valuable adjacent alternative: move/resize + style inspector**. Existing rectangles/ellipses are currently create/delete only. Manipulation and color/weight edits make every existing and future markup substantially useful. A transient compact properties popover avoids permanent toolbar growth. This is likely better general utility than adding several more fixed-red tools.
3. **Text boxes next**: arrows without explanatory notes cannot express a complete review comment. More complexity (typing/focus/font/appearance), but high architectural-review value.
4. **Go to Sheet** is the strongest small non-markup alternative: reuse labels/bookmark summaries, searchable picker, keyboard navigation, duplicate labels as separate results. Much lower persistence risk than OCR or flattening.
5. **OCR regions + editable bookmark review** is the largest drawing-set parity blocker, particularly for scanned consultant sets. Scope as a separate staged effort with selectable-text-first fallback, explicit preview/apply, cancellation, duplicate handling and source-preserving outputs. Tabs/printing follow actual user frequency; reversible flattening/reduction require dedicated correctness work, not quick button enabling.

### Non-negotiable save integration gate

For any new annotation or geometry/style change, extend the edit model, shared history, serialized ownership/appearance, and **staged save verification together**. Current staging compares shape records, outline/labels, and PDF objects (`G/src/pdf/edit_session.rs:600–650`); new kinds and properties must be represented in the record comparisons. Preserve import content, crop/rotation coordinate mapping, conflict/backup behavior, no-clobber Save As, and preview-failure recovery (`G/src/app/editing.rs:183–203`). Verification should later use synthetic rotated/cropped PDFs, external-change races, undo/redo, save/reopen and independent rendering. This audit intentionally did not run those tests.
